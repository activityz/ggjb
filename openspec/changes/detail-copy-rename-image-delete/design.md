# 设计：规格改名、可选中复制、图片删除入口

## 关键决策

### D1 改名只动「人看得见的名字」，不动数据

三处：
1. `item_edit_page.dart` 的 `label: '内存规格'` → `'规格'`
2. `item_detail_page.dart` 的 `_attrRow('内存规格', …)` → `'规格'`
3. `dict_seeds.dart` 的 storage 组标签 `'内存规格'` → `'规格'`（字典管理里看到的分类名）

**不动 Excel 表头**：它本来就叫「内存」，改它会让旧导出文件的导入走别名兜底，白白多一条兼容路径要维护。

**不迁移历史数据**：字段名是常量，库里存的是用户选的**值**（`128G` 之类），改名不影响任何记录。

### D2 用 `SelectionArea` 包整页，而不是把每个 `Text` 换成 `SelectableText`

`SelectionArea` 让区域内所有文字可选中，而 widget 树里仍然是普通的 `Text`。这一点很关键：

- **不改现有断言**：测试里大量 `find.text('…')` 直接命中 `Text`，换成 `SelectableText` 后 finder 语义会变，一堆用例要跟着改。
- **不抢手势**：`SelectableText` 自己实现长按选择，会把长按从父级 `GestureDetector` 那里抢走——而图片格子、商家保修补填这些行正是靠长按/点击的。`SelectionArea` 不改变子树上已有的手势竞争，行内点击、长按照样生效。
- 触摸端长按选词、桌面端鼠标拖选 + `Ctrl+C`，都是系统标准行为，不用自己写。

范围：只包详情页的内容区（`_body` 返回的 `ListView`），不包底部按钮区。

### D3 大图里补「删除」，走已有的确认流程

大图右上角现有「保存」＋「关闭」，再加一个「删除」，三个并列。

行为：

- 点「删除」→ 弹现有的确认框（`_confirm('删除这张图片', …)`）
- **确认**：先关大图，再删（删除后那张图已经从数据源消失，大图留在屏幕上就是一张没有归属的图）
- **取消**：什么都不做，大图保持打开

保留长按格子删除的老路，不动它。

### D4 删除按钮放哪一侧

放最左边，顺序「删除 · 保存 · 关闭」——破坏性的动作离手指最远的那一端，且不放第一个。按钮用 `Colors.white` 图标配黑色半透明底，与「保存」同款，保证在任意图片上都看得清。

## 被否掉的方案

| 方案 | 否掉的原因 |
| --- | --- |
| 每个值换 `SelectableText` | 会抢长按；一行行换还有几十处 |
| 加「复制」图标按钮（用户明确不要） | 需求就是不要按钮 |
| 点一下值就复制到剪贴板 | 隐性手势，误触就把内容顶掉了，且没有系统反馈 |
| 删除入口只放在长按菜单里（现状） | 用户已经找不到，等于没有 |
| 删除时把大图留在屏幕上 | 图没了还开着弹窗，看着像没删掉 |
