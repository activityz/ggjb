# expense-identity

费用的「编号」在导出、导入这条路上必须留得住：同一笔费用来回一趟还是同一行，
而不是每导一次就多一条新记录、多一条墓碑。

## ADDED Requirements

### Requirement: 导出必须写出费用 id

费用表 SHALL 在第一列写出「费用id」，值为 `expenses.id`；其余列顺序不变。
费用行的内容与今天一致（商品id、商品名称、种类、侧别、金额、发生日期、备注）。

#### Scenario: 导出的费用表首列是费用 id

- **WHEN** 库里有一条 id 为 `e1` 的费用挂在商品 `a` 上，且调用导出
- **THEN** 费用表表头第一项是「费用id」
- **AND** 该行的第一格是 `e1`

#### Scenario: 软删的费用不导出

- **WHEN** 一条费用的 `deleted_at` 非空
- **THEN** 导出的费用表里没有它（与今天一致）

### Requirement: 带 id 的费用导入时原地覆盖

导入 SHALL 读取「费用id」列。当该 id 在本地已存在（含已软删）时，导入必须
原地复活并覆盖这行，不得新增行，也不得把旧行打成墓碑。

#### Scenario: 重复导入同一份表不增加行数

- **WHEN** 先导出一次，紧接着把这份表再导入一次
- **THEN** 该商品的费用行数不变
- **AND** 费用 id 与第一次导出一致

#### Scenario: 本地已软删的费用被复活

- **WHEN** 本地费用 `e1` 的 `deleted_at` 非空，导入表里带 `e1`
- **THEN** 导入后 `e1` 的 `deleted_at` 为空
- **AND** 金额、种类、侧别按表里的值覆盖

### Requirement: 没有费用 id 列的旧文件照样能导入

「费用id」列缺失时，导入 SHALL 按「没有 id」处理：插入新费用行，
不得因为缺列而报错或整张表跳过。

#### Scenario: 旧格式文件导入成功

- **WHEN** 导入一份表头不含「费用id」的旧导出文件
- **THEN** 预览无错误
- **AND** 费用按新行写入

### Requirement: 费用 id 不能重复

同一份表里同一个费用 id 出现两次 SHALL 报错，提示具体行号，
并且整份预览不可写入。

#### Scenario: 两行写了同一个费用 id

- **WHEN** 费用表第 2 行与第 3 行的「费用id」都是 `e1`
- **THEN** 预览报错，信息含「费用id」与该行号
- **AND** `preview.ok` 为 false
