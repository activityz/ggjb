# 设计：详情页字段与编辑页对齐

## 现状对照（读代码得出）

| 字段 | 编辑页 | 详情页（改前） |
| --- | --- | --- |
| 名称 | ✅ | ✅ 标题 |
| 品牌 / 型号 / 内存规格 / 颜色 | ✅ 四个独立输入框 | ⚠️ 拼成一行 11px 灰字，无字段名 |
| **分类** | ✅ | ❌ 完全不显示 |
| **序列号** | ✅ | ❌ 完全不显示 |
| 买入价 / 买入日期 / 买入来源 / 买入成色 / 电池健康 | ✅ | ✅ |
| 厂家保修状态 | ✅ 三态 | ⚠️ 「无保修」时不显示任何东西 |
| 厂家保修起止 | ✅（在保才填） | ✅（在保才显示） |
| 状态 | ✅ | ✅ Chip |
| 卖出价 / 卖出日期 / 卖出渠道 / 卖出成色 / 挂牌价 | ✅ | ✅ |
| 商家保修起止 | ✅ | ✅（未填给补填入口） |
| 费用 | ✅ 多条 | ✅ 费用明细 |
| 备注 | ✅ | ✅（有才显示） |

结论：真正缺的是**分类**与**序列号**两行；品牌四项是「有但不成形」；厂家保修是「少一态」。

## 关键决策

### D1 新增一块「商品属性」卡，放在标题之后、利润卡之前

商品属性回答「这是什么机器」，利润卡回答「这单赚了多少」。看货的人先确认机器，再看钱，顺序不变但属性从「一行小字」升级成独立区块。

位置：标题 / 置换徽标 之后，利润卡 之前。

### D2 六个字段一律用「字段名 + 值」的两列行

复用详情页已有的 `_kv` 写法（左侧固定宽度标签、右侧值），与「时间与渠道」那块一致，视觉上不用新造轮子。

顺序照编辑页：品牌 → 型号 → 内存规格 → 颜色 → 分类 → 序列号。

不做的：不给属性卡加图标、不加玻璃材质分层——它是一张信息卡，不是装饰。

### D3 缺值显示「—」而不是隐藏

分类、序列号都是非必填。隐藏会让「没录」和「这一栏根本不存在」混在一起，而这两件事对用户意义完全不同（前者可以补，后者会以为程序不支持）。所以固定六行，没填就是「—」。

### D4 厂家保修补「无保修」一行

只在状态为 `none` 时多显示一行「厂家保修：无保修」。原有「已过保」「在保起止」保持不动。

这与老代码里那句注释的取舍不同（当初怕老记录看起来变脏），但用户这次明确要求「字段要和编辑页一致」，三态必须都能看见。

### D5 不整页重排

编辑页的分组是「买进来 / 厂家保修 / 卖出情况 / 费用 / 备注」，详情页是「利润 → 费用 → 时间与渠道 → 图片 → 备注 → 保修卡 → 改状态」。后者把财务放前面是刻意的，重排会打乱常用动线，属于范围外改动。本次只补字段与属性排版。

## 被否掉的方案

| 方案 | 否掉的原因 |
| --- | --- |
| 整页按编辑页分组重排 | 打乱「先看钱」的动线，改动面大，用户没要求 |
| 把品牌四项做成一行但加小标签（`品牌 Apple · 型号 13`） | 仍然是一行，长值会挤成一团，且不满足「按字段名和值展示」 |
| 属性卡里加编辑入口 | 详情页只读，改资料走编辑页，多一个入口只会分散 |
| 缺值就隐藏该行 | 分不清「没录」与「不支持」，见 D3 |
