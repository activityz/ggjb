# 设计：保修卡换新条款、去掉成色

## 依据

用户的选择：「**卡片不变**，条款内容和我给你发的一致就行，字号间距排版你随意调整」。所以尺寸锁死 360×540（1080×1620），办法只能从排版里挤。

## 实测数据

- 新条款正文：**540 个字符、18 个非空段**（含四组小标题与温馨提示）
- 内容宽度：360 − 左右 padding 40 = **320px**
- 各字号下的估算（中文字宽≈字号，行高按 1.32）：

| 字号 | 每行字数 | 折行后总行数 | 条款区高度 |
| --- | --- | --- | --- |
| 8.5（现状） | 37 | ≈ 24 | ≈ 264px |
| **7.5（采用）** | **42** | **≈ 22** | **≈ 218px** |
| 7.0 | 45 | ≈ 21 | ≈ 193px |
| 6.3 | 50 | ≈ 19 | ≈ 160px |

## 空间预算（卡面 540 高，上下 padding 34，可用 506）

| 区块 | 改前 | 改后 | 说明 |
| --- | --- | --- | --- |
| 卡头（logo + 标题 + 日期） | 36 | 36 | 不动 |
| 蓝线 + 间距 | 22 | 18 | 收 4 |
| 商品标题 | 40（2 行） | 22（1 行） | 收 18，超长省略 |
| 属性 kv | 54（3 行） | 36（2 行） | **删成色**省 18 |
| 商家保修框 | 50 | 46 | 内边距 10→8 |
| 分隔线 + 「保修条款」 | 22 | 18 | 收 4 |
| **条款区** | 81（旧三条） | **218** | 新四部分 |
| 二维码行 | 60 | 56 | QR 56→52 |
| 合计 | ≈ 365 | ≈ 450 | 余量 ≈ 56 |

结论：装得下，不需要动尺寸。

## 关键决策

### D1 条款正文 7.5、小标题 8.2、行距 1.3、条目间距 1.2、节间距 2

3 倍截图下正文是 22.5px 实像素，1080 宽的图在手机上放大看、按 A4 打出来都还清楚。

这几个数是**被 overflow 测试逼出来的**：先写 7.5 估算能过，实测溢出 35px；收到 7.2 才通过（余量偏大），再往上试 8.0 与 7.8 都溢出 1.6px（正好多折一行），最终落回 7.5 通过。再往下（≤7）就没有余量了：店主以后再加两句就得回头改尺寸，那不叫省，叫埋雷。

### D2 条款改成「分节」结构，文本逐字照抄

`WarrantyCardView.terms` 从「三行字符串」改成「四节 + 温馨提示」：

```dart
class CardTermsSection {
  const CardTermsSection(this.heading, this.items);
  final String heading;        // 如「二、不在保修范围（免责条款）」
  final List<String> items;    // 条目，逐字照抄
}
```

编号「一、二、三、四」、条目里的「1. 2. 3.」、括号注释、结尾「温馨提示：」全部保留原文，不改写、不缩写。

### D3 商品标题限 1 行

标题超长时省略号截断。卡面不是列表，标题只是认出是哪台机器；型号那行已经能补足信息。

### D4 用测试守住「装得下」

widget 测试里渲染卡面并断言：

1. 四组标题、温馨提示、五条免责条款的首句都能找到；
2. 旧简版条款文字找不到；
3. 卡面找不到「成色」；
4. 截图仍是 1080×1620；
5. **渲染期间没有 overflow 异常**（`tester.takeException()` 为空）。

第 5 条是关键：以后谁再往条款里加字，测试会先红，而不是等用户发现卡面被截断。

### D5 旧卡不重做

已生成的保修卡图存在附件里，不动它。用户重新生成时才印新条款——手上已经发出去的凭证不该突然变样。

## 被否掉的方案

| 方案 | 否掉的原因 |
| --- | --- |
| 卡面加长到 1080×2280 | 用户明确「卡片不变」 |
| 只印四个小标题 + 「详见店内说明」 | 用户要求条款内容与给的一致，摘要等于没印 |
| 凭证 + 条款页两张图 | 一次生成两张会让「查看/重置/导出」全部变成两套逻辑，收益不抵复杂度 |
| 字号压到 6.3 | 3 倍截图下 19px，打印后偏小；而且一点余量都不留 |
