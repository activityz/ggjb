# 进化日志

> 只记三档进化机制里的「可自主」部分：识别到的进化机会、记忆落盘动作、被废弃的旧结论。
> 需要用户确认的动作（新建 skill / 改工作流 / 写知识库）单独申请，不记在这里。

## 2026-10-30

- 新建 `docs/agent/memory.md`：把版本锁、环境约束、drift/Riverpod/file_picker 的坑、算钱纪律固化下来。
  这些是「不写下来下次一定再踩一遍」的内容。
- 结论修正：局域网同步从「记录级增量 + 独立附件通道」改成「整库快照交换」。
  理由：增量协议要自己维护墓碑、断点续传和图片一致性校验，出错面远大于收益；
  千级记录的快照只有几十 MB，一次传完更简单可靠。
- 结论记录：`StatDao` 的聚合必须复用 `ProfitCalculator`，不能在 SQL 里另算一遍金额，
  否则看板和详情页会出现两套口径。
- 环境结论：Gradle wrapper 发行包的下载锁冲突（`Timeout of 120000 reached waiting for exclusive
  access to file`）不是网络问题，而是**并发构建抢锁**。同一时间只允许一个 `flutter build`；
  本地已有解压发行包时，用目录联接 + 空的 `.ok` 标记让 wrapper 跳过下载。已写进 memory.md 第 4 节。
- 结论修正：视觉方案从「性能红线优先」改成「效果规格优先」。
  原来的每屏模糊 ≤2 层、粒子 40 个这类硬上限，是按中端机 60fps 反推的；
  用户明确要求「效果做到最好，暂不考虑性能问题」后，这些数字全作废，
  只保留一条品味底线（粒子透明度 0.06~0.14、发光只给金额不给边框），
  因为深色 + 玻璃 + 粒子叠在一起，不加克制就会变成廉价炫光。已写进 memory.md 第 8 节。
- 流程结论：改动前必须走「澄清 → 计划待批 → 编码」，不得读几个文件就自拍设计决定直接改代码。
  用户对这条的纠正见本轮对话；另外**产出安装包的构建命令必须等用户开口**才能跑，
  `build_runner` / `analyze` / `test` 属于本地校验可以自行执行。
- 操作教训：把 `body:` 从单 widget 改成 `Stack` 时闭合层数要整体加两层，已连错三轮。
  正确顺序（`],` → `),`×3 → `if` → `],` → `),` → `);`）已写进 memory.md 第 8 节，改之前先数括号。
- 操作教训：`terminal_send` 在 PowerShell 下会逐字符回显，屏幕上看起来像乱码，
  **但不代表命令没执行**——判断依据只能是脚本写的日志文件，不能看回显。
  同一 pty 反复无响应时，开新 session 比在旧 session 上重发可靠。
