## 问题 1：编辑商品时报 `UNIQUE constraint failed: expenses.id`

**现象**

```
保存失败：SqliteException(1555): while executing statement,
UNIQUE constraint failed: expenses.id, constraint failed (code 1555)
INSERT INTO "expenses" (...)
```

**根因**

`app/lib/data/repo/item_repository.dart` 的 `save()` 里，费用用的是「全量替换」策略，但实现顺序错了：

1. 先把该商品的所有 expense 打墓碑（只写 `deleted_at`，**行还在**）；
2. 再拿表单里的 id 逐条 INSERT。

第 2 步用的是同一个 id，行没被物理删掉，主键必然冲突。只有「新建一笔费用」不会触发，**只要编辑已有费用就必然报错**。

**方案**

不物理删、也不盲目重插，改成按「这次提交的 id 集合」分两种情况：

| 情况 | 处理 |
| --- | --- |
| 旧行这次没提交（被删掉的那条） | 打墓碑（保留墓碑给对端，否则对端会复活它） |
| 提交的 id 本地已存在 | 复活 + 覆盖，`deleted_at = null` |
| 提交的 id 本地不存在 | 插入新行 |

`createdAt` / `deviceId` 一律不覆盖 —— 那是「谁在什么时候建的」，编辑不该改。

**注意点**：`isNotIn` 传空集合会生成 `NOT IN ()` 这种非法 SQL，所以只在 `keepIds` 非空时才加这个条件。

## 问题 2：详情页「标记已卖出」的卖出价可以不填

**现象**

弹窗里 `hintText` 写的是「留空按 0 计，即白送」，确定按钮直接放行，代码里 `sellPriceCents: sell?.cents ?? 0`。

**后果**：用户点确定跳过价格，这一单就被记成 0 元卖出，毛利直接变成负数，而用户以为自己只是「还没填」。

**方案**

- 弹窗改成 `StatefulBuilder`，确定时先校验：空 → `必须填卖出价`；非数字 → `格式不对，填数字`；校验不过不关弹窗、把错误挂在输入框 `errorText` 上。
- 真正白送也得**显式填 0**，不能靠留空。
- 去掉 `?? 0` 兜底，解析不出就中止并提示。

## 问题 3：详情页信息顺序（用户 m03657）

费用明细从第 3 位提到第 2 位，新顺序：

> 利润卡 → 费用明细 → 时间与渠道 → 图片 → 备注 → 改状态

理由：费用是「毛利为什么是这个数」的拆解，属于财务主线；时间、渠道、成色是商品属性，往后排。费用区同时改成**始终显示**（没费用时给空态说明），否则用户不知道这里能记账。

## 验收

| 项 | 方式 |
| --- | --- |
| 编辑已有费用能保存 | 改一条费用金额 → 保存 → 不报 1555 |
| 删掉一条费用能保存 | 删行 → 保存 → 该行墓碑、列表消失 |
| 卖出价必填 | 标记已卖出 → 清空价格 → 确定 → 弹「必须填卖出价」，不关窗 |
| 卖出价 0 可保存 | 填 0 → 确定 → 保存成功，毛利 = −(买入价 + 费用) |
| 详情页顺序 | 进详情页 → 费用明细在利润卡下面 |
| 静态检查 | `flutter analyze` 0 issue；`flutter test` 72 项全过（已完成） |
